# Before this conversation becomes hard to find

**Recipe only. No scheduled task is installed or authorized by this file.**

## Optional: recover previous sessions first

Participants can bring selected, permitted exports into [the Muck archive](../%5FMuck/ABOUT.md). Follow its import rules and review process. Keep the historical sources separate from current instructions. Reviewed links can enter the constellation; only accepted current tasks enter the One List. Never scan an unreviewed full-account export to decide what was private. This is a folder-based archive, not a requirement to paste everything into one prompt.

## Tend current work manually, then consider a schedule

Near the end of a conversation, you may want to keep a place to return. We were thinking about this; that is still open; here is the file. It can be small.

Start manually: “Review only this project’s approved handoff notes and tell me what should be updated.” The guide reads those notes, proposes task or project changes, and shows them for review. It keeps a source pointer for accepted changes. New personal context still needs permission; an unknown does not become clearer merely because this is the closing note.

Perhaps nothing needs updating. Leave it there. The usefulness of the conversation does not depend on producing evidence that a conversation occurred.

After a successful manual run, the participant may choose a recurring job in an app that actually supports it. Verify current capability and cost first. Agree exact sources, excluded areas, write destinations, allowed automatic updates, local time/timezone, frequency, stop date or review point, and notification preference. Never assume access to chat history from another app or account.

A possible scoped job instruction, to customize BEFORE enabling:

“Read only the session notes explicitly approved for this project. Skip all private, excluded, unapproved, or inaccessible material without inspecting it. Propose updates to the project handoff and one task list. Record the source note and which notes were already processed, without copying their sensitive contents. Do not overwrite newer human edits. Do not add personal context, new commitments, cultural interpretations, relationships, or cross-project material. If there is no actionable change, stay quiet. Report a meaningful change, failure, or required decision. Stop if permission or access is unclear.”

This is optional later setup, not a workshop exercise. Before enabling unattended changes, verify the scoped job on explicitly permitted non-sensitive notes. Run again on the same notes: it should not duplicate tasks. Test a corrected task, an excluded area, missing access, and a human edit made since the last run. Then inspect the actual scheduler, verify its next run, and show how to pause or disable it. A saved prompt is not a running schedule.

If scheduling is unavailable, keep the manual “tend this session” action. Do not require the person to export all their conversations to obtain continuity.
