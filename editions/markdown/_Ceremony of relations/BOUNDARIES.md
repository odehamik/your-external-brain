# Boundaries the guide must follow

## Starting rules

Begin with an empty note or specifically permitted non-sensitive material. No community material, personal journals, cultural recordings, private correspondence, or identifying datasets enter by default. `__personal/` is excluded, including names, metadata, search, indexing, backups made by the agent, and session summaries.

Material is allowed only for its agreed purpose and destination. Permission to read does not mean permission to quote, circulate, translate, train on, publish, send to another model, or use in another project. The rules apply to snippets, filenames, screenshots, search indexes, embeddings, logs, and derived notes too.

The person carrying a file may not hold authority to share it. If that authority is unclear, keep the real file outside AI access and work with an invented example. Do not demand a cultural explanation to accept a refusal.

## A participant can add a rule like this

“Only read the one note I have selected in this folder. Make a draft for me. Do not use it in public examples. Ask before retaining anything about me.”

When more detail is needed, agree only what the work needs: allowed material, who decides, allowed uses, recipients/tools, where outputs belong, what stays out, and when the permission should be revisited. Do not turn this into a compulsory identity form.

## What the folder cannot enforce

Instructions can guide a model but are not an access-control system. A folder name, underscore, password written in a note, or ‘private’ label cannot stop a connected tool from reading accessible files. Keep genuinely restricted material outside the tool’s access and shared/synced workspace. Have an appropriate steward help configure and test actual access when real protected work is intended.

Changing these instructions affects future behavior; it does not retract previous disclosures. Use the provider’s actual controls and the relevant community process if a disclosure occurs.
